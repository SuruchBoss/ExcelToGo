# ExcelToGo กับ PaynEat ERP

**English:** [payneat-erp.en.md](payneat-erp.en.md)

- **สถานะ:** ตอบรับเข้าร่วมระบบนิเวศ PaynEat แล้ว (2026-09-26) **แต่ยังไม่ได้สร้างอะไรเลย** ทุกข้อด้านล่างคือแผน
  ไม่ใช่ฟีเจอร์ที่มีอยู่
- **ฝั่ง ERP:** [ADR-0011](https://github.com/SuruchBoss/PaynEat-ERP/blob/main/docs/adr/0011-ecosystem-and-sherwhyve.th.md)

  (ต่อยอดผ่าน API เท่านั้น), [`TELEMETRY.md`](https://github.com/SuruchBoss/PaynEat-ERP/blob/main/docs/TELEMETRY.md) v1.2

## หลักที่ไม่เปลี่ยน

- **ExcelToGo ยืนได้เองเหมือนเดิม** คนที่ไม่ได้ใช้ ERP ต้องไม่เห็นอะไรเปลี่ยน ของที่เป็นของ PaynEat โดยเฉพาะอยู่ใน
  แม่แบบหรือในค่าที่ operator ตั้งเท่านั้น ไม่อยู่บนหน้าหลัก
- **ต่อ ERP ผ่าน public API เท่านั้น** ห้ามใช้ [แหล่งข้อมูลฐานข้อมูล](../README.md#-ต่อฐานข้อมูลตรง-ๆ-postgresql--mysql)
  กับฐานข้อมูลของ ERP โครงสร้างตารางของ ERP ไม่ใช่สัญญา และการอ่านตรงข้าม audit trail ของ ERP
  **ExcelToGo บังคับข้อนี้ด้วยโค้ดไม่ได้** เพราะรายชื่อ host ที่ต่อได้เป็นของ operator ฝั่ง ERP จึงควรปิดทางเครือข่าย
  ไปยังฐานข้อมูลของตัวเองอีกชั้นหนึ่ง
- **ข้อมูลในชีตไม่ออกจากเบราว์เซอร์** เหมือนเดิม ข้อมูลที่ดึงจาก ERP มาแล้วก็อยู่ในเบราว์เซอร์ของคนที่เปิดดู

## งานที่ตกลงกัน

| งาน | ใครเป็นเจ้าของอะไร | เมื่อไร |
|---|---|---|
| **แม่แบบนำเข้าข้อมูล** | ERP เป็นเจ้าของรูปแบบแม่แบบ (ชีต คอลัมน์ กฎ) และ endpoint นำเข้า และตรวจซ้ำทุกแถว ExcelToGo เปิดแม่แบบ ช่วยให้กรอกถูก และส่งออก `.xlsx` ที่กฎยังครบ | หลัง ERP v1 ก่อนมีเชนนำร่อง |
| **ดึงข้อมูลสดจาก public API ของ ERP** | ERP ออก API และ token แบบอ่านอย่างเดียว ExcelToGo เป็นผู้ใช้รายแรก | หลัง ERP ออก public API |
| **`x-request-id`** | ExcelToGo ส่ง header นี้ทุกคำขอ ตามรูปแบบใน `TELEMETRY.md` | เมื่อไรก็ได้ |

## แม่แบบนำเข้า: ทำได้แล้วแค่ไหน

**ทำได้แล้ว:** เปิดไฟล์ที่ล็อกชีตไว้เป็นแม่แบบ (ช่องที่ปลดล็อกคือช่องให้กรอก), dropdown ที่เขียนเป็นรายการในสูตร
(`"kg,g,pcs"`), และกฎ `list` / `decimal` / `textLength` เข้าออก `.xlsx` ได้

**ยังขาด ต้องทำก่อนส่งแม่แบบให้เชนใช้:**

1. **บั๊ก: dropdown ที่ชี้ไปช่วงเซลล์ในชีตอื่นได้ตัวเลือกผิดชุด** กฎอย่าง `=Ref!$A$2:$A$50` ถูกอ่านจากช่วงเดียวกัน
   *ในชีตที่เปิดอยู่* แทนชีต `Ref` (`src/lib/excelIO.ts`, `rangeReader`) โดยไม่มีคำเตือน
2. **บั๊ก: dropdown ของแม่แบบถูกเขียนกลับโดยไม่เช็กเพดาน 255 ตัวอักษรของ Excel** กฎที่ผู้ใช้สร้างเองมีตัวกันนี้แล้ว
   แต่ของแม่แบบยังไม่มี รายการรหัสสินค้ายาว ๆ จึงได้ไฟล์ที่ผิดสเปก
3. **ต้องเก็บ "การอ้างอิงช่วง" ไว้ทั้งไปและกลับ** ถึงแก้ข้อ 1 แล้ว ตอนนี้ตัวเลือกก็ยังถูกถ่ายเก็บเป็นรายการ ณ ตอนนำเข้า
   แล้วเขียนกลับเป็นรายการในสูตร รายการหลายพันรหัสจึงไม่มีทางผ่านเพดาน 255 ตัว ต้องเก็บ `Ref!$A$2:$A$5000`
   ไว้ทั้งเส้นทาง รวมถึง**สถานะซ่อนและการล็อกของชีตอ้างอิง** ซึ่งตอนนี้หายไปตอนส่งออก
4. **ขนาด:** ที่วัดแล้วคือ กริดเรนเดอร์เฉพาะแถวที่เห็น (CSV 5,000 แถวมีแค่ 41 แถวใน DOM) และชีต 3,000 แถวที่มีสูตร
   9,000 ช่องคำนวณใหม่ต่อการแก้หนึ่งครั้งในหลักมิลลิวินาที **ที่ยังไม่ได้วัด** คือ dropdown หลายพันตัวเลือก
   บนหลายพันแถว จะวัดจากไฟล์แม่แบบตัวอย่างของ ERP ก่อนให้ตัวเลข

## ข้อมูลสด: สิ่งที่ ERP ต้องรู้

- **ต้องติดตั้ง ExcelToGo เอง** ข้อมูลสดใช้บนเว็บตัวอย่างที่อยู่บน Vercel ไม่ได้อยู่แล้ว เพราะ config ถูกเก็บใน
  `data/sources.json` ซึ่ง filesystem ของ Vercel เขียนไม่ได้
- **รูปแบบการแบ่งหน้าที่แนะนำ:** body แบบ `{ "data": [...], "next": "<URL เต็ม บน host เดียวกัน>" }`
  โดย `next` เป็น `null` ที่หน้าสุดท้าย และตอบ `429` พร้อม `Retry-After` เป็นวินาทีเมื่อถูกจำกัด
  ตัวไล่หน้ารู้จัก `Link: rel="next"`, cursor ใน body และ `?page=` / `?offset=` ด้วย
  ([paginate.ts](../src/lib/dataSources/paginate.ts), [rateLimit.ts](../src/lib/dataSources/rateLimit.ts))
- **เพดานต่อการรีเฟรชหนึ่งครั้ง:** 20 หน้า, 50,000 แถว, 15 วินาทีต่อคำขอ, 45 วินาทีรวม ถ้าต้องการครบ 50,000 แถว
  ERP ต้องส่งอย่างน้อยหน้าละ 2,500 แถว
- **token หนึ่งตัวต่อหนึ่งการติดตั้ง ไม่ใช่ต่อคน** แหล่งข้อมูลของ ExcelToGo เป็นของทั้ง deployment
  audit trail ของ ERP จึงเห็นว่า "ExcelToGo" เป็นคนเรียก ไม่เห็นว่านักบัญชีคนไหน ควรออก token ที่มี scope
  แคบที่สุดที่รายงานต้องใช้
- **ERP ในเครือข่ายภายใน:** วันนี้ ExcelToGo บล็อกที่อยู่ภายในทุกช่วง แม้ host จะอยู่ใน `SOURCES_ALLOWED_HOSTS`
  แผนคือเพิ่มรายชื่อ host ภายในที่ operator ระบุทีละชื่อ โดย**ยังบล็อก loopback, link-local และ cloud metadata เสมอ**
  และมีเทสต์กันไว้ ซึ่งเข้มกว่า `SOURCES_ALLOWED_DB_HOSTS` ที่ข้ามการเช็กที่อยู่ทั้งหมด งานนี้มาพร้อมการทบทวน
  เส้นทางการ fetch ทั้งเส้นก่อนเปิดใช้

## `x-request-id`

ส่งค่าใหม่ทุกคำขอ รูปแบบต้องผ่าน `^[\w-]{8,64}$` ตาม `TELEMETRY.md` v1.2 ไม่อย่างนั้น ERP จะสร้างค่าใหม่เอง
และโยงกลับไม่ได้ ส่วนการเขียน log ของ ExcelToGo ตามสัญญา telemetry ยังไม่อยู่ในแผน
